## P0：固定资产与离线检查

实施 02、03。保留源 ZIP、旧 EXE、EPW 和归档代码；检查函数仅返回结构化报告，命令行只向标准输出打印 JSON。指纹来自实际读取的同一份字节快照，不能先检查路径再读取另一份内容作为核验对象。

发布包检查覆盖指定身份、CRC、入口和依赖的 PE 架构以及 PyInstaller 的 Python 元数据。它不执行 EXE、不解包到源目录，也不输出“已运行”状态。因为先固定整包指纹，该工具不是可接收任意 ZIP 的通用安装器。

天气检查覆盖单个全年、每小时一条记录的顺序、35 列结构、时间字段、12 个气象量的缺测和范围，以及两项跨字段一致性诊断。它不改写天气、不填零、不选择模拟日历，也不证明全部 EPW 字段或新版解析器可用。`Line` 和 `*_lines` 指包含八条头记录在内的 CSV 记录号。

验收断言：指定 ZIP 的静态身份正确；其他字节内容被拒绝；广州 EPW 保留其原始字节和时间元数据；同样有 8760 行但重复小时的输入被拒绝；缺测、非有限值与字段越界产生可定位诊断；改变来源年份不会改变月/日/小时序列的检查结果。两个报告中的运行兼容状态始终为 false。

资产登记延续 [DATA.md](DATA.md)。检查工具本身不创建数据登记或测试报告文件；未来保存报告、派生天气或运行基准时，须同时记录来源指纹、生成方法、用途与质量状态，不能把静态结构检查升级为数值质量认证。

## P1：确认新版引擎和宿主边界

P0 后可先在 Linux 上沿已恢复反汇编核查协议，原版运行和 Rhino 宿主验证分别开展。启动候选显式指定 `cwd`，按其父目录下 `Projects/<building>/<run>` 组织文件；正式 CLI 固定 `order=1`，不提供未经支持的二阶开关。已确认 `weather_mode` 的非 default 值直接传给天气读取器，不能按名称实现插值选项。

运行验证优先采用上游双热区费城样本，在派生副本中记录天气路径替换，再测试上海办公样本。写出器候选须保留天气路径行的 `!!!` 分支，以避免已发现的冒号截断；样本扫描器的首冒号规则不能替代引擎实际行为。历史 CSV 保留作结构证据，新版数值基准由实际运行生成。

当前可见太阳路径使用 `Solar/AreaFrac`，尚未找到可用的独立 `.sol` 读取协议；直接将两字段写入 `.sim` 还有类型失配风险。外部太阳输入继续作为能力缺口，先确认有效读取路径再给出写出格式，无需用户另行提供现成文件。

| 案例 | 必须记录的输入和观察 | 完成判据 |
|---|---|---|
| 启动与调用 | 包指纹、系统环境、完整参数向量、工作目录、退出码、标准输出/错误 | 找到实际启动方法；错误输入产生可追溯证据 |
| 最小单热区 | 人工控制条件、候选字段、全部文件字节及引用 | 新版接受输入并产生可解析的本次产物；不依赖历史残留文件 |
| 天气和日历 | 广州 EPW、首尾小时、来源年份、分钟、起始星期、日程对应 | 确定实际索引和区间含义；无静默重排、丢日或错位 |
| 太阳输入 | 无外部序列、仅窗序列变化、仅不透明序列变化、仅后续热区提供序列 | 确认可选性、顺序、单位、面积归一化、长度和有效作用；不能凭文件读取成功宣称有效 |
| 非空调耦合 | 受调节房间与非空调缓冲区；改变接触面积或邻区边界 | 自由室温和相邻传热真实响应；不靠极端设定温度代替非空调状态 |
| 坡面与方向 | 正交、旋转、非正交及坡屋顶控制模型 | 明确方向/倾角表达和近似边界；不静默投影或吸附至旧八方向 |
| 结果语义 | 原始表头、单位依据、逐时记录、累计量、峰值、各区室温 | 建立逐量语义和时间轴；输出存在或退出码为零不足以判定成功 |
| 名称与路径 | 中文用户名称、含空格目录、区域小数格式 | 确定协议名映射和编码；用户名称不直接拼入命令或路径 |

新版太阳覆盖分支对 `q_sol_op` 使用赋值，不能沿用旧 `Solar_OP` 比较缺陷的表述。首热区没有 `Solar` 时跳过全部外部覆盖已由新版静态指令确认；输入字符串乘法导致异常则是待运行验证的推断。测试参数明确标记为人工条件，失败案例和原始日志保留；没有有效输出时不生成模拟成功报告。

宿主验证检查 Python 包导入、组件发布/安装、重复 GH 求解、后台完成、文档关闭及取消竞争。官方 Script Editor 可发布 `.gha` 和共享代码库，但实际最低 Rhino 8 小版本必须经安装验证确定。GH 不支持通过 `# async: true` 获得异步组件；后台等待与回写需遵守宿主调度约束，不能把普通线程完成等同于可以直接修改 GH 文档。[项目发布](https://developer.rhino3d.com/guides/scripting/projects-publish/)、[异步脚本限制](https://developer.rhino3d.com/guides/scripting/advanced-async/)

本阶段交付经登记的候选/有效输入、原始产物、失败证据、接口映射和宿主版本矩阵。若新版无法表达非空调、坡面或外部太阳需求，应提交明确能力差距；不能悄悄缩减已接受需求或在结果层补偿内核。

## P2：定稿跨阶段数据契约

以下是必须定稿的信息边界，具体 Python 类型名、schema 版本、持久化格式和函数签名不在本文冒充已批准接口。核心接受普通 Python 数据，不接受 Brep、GH_Goo、DataTree 或翻译后的引用键。

| 接口边界 | 必需信息 | 定稿时必须保证的不变量 |
|---|---|---|
| 几何适配 → 核心 | 热区/面的稳定标识、几何量、朝向、北向、面积、体积、边界类型、邻区与接触面积 | 相邻关系一致；窗与不透明面积不重复；几何不确定性有对象定位 |
| 工况 → 热区 | 空调状态、人员/设备/照明、通风渗透、设定温度、各类日程、来源及覆盖值 | 非空调与无人、无内部得热分别表达；比例日程与温度日程不混用 |
| 天气 → 日程/太阳/引擎 | 源文件指纹、地点/时区、原始时间字段、模拟日历、逐记录区间 | 来源年份和模拟年分离；全部序列显式对齐，不用机器区域设置推导 |
| 太阳前处理 → 协议 | 所属热区/面、窗和不透明部分、序列物理量、单位、面积基础、时间轴 | 在新版语义已确认后转换；同一遮挡作用不重复折减 |
| 方案 → 运行 | 方案标识、运行标识、完整输入快照、引擎/天气/预设指纹、研究变量 | 同一方案多次运行可追溯；后续 GH 编辑不改变已提交输入 |
| 运行 → 结果 | 运行状态、产物清单、日志、表头、单位、时间轴、能源边界、对象映射 | 本次来源明确；缺列/失败不填零；终态确定 |
| 结果 → 比选 | 共同条件、各方案差异、面积和服务口径、有效指标 | 先判断可比性，再计算差异；失败项保留状态 |
| 核心 → 呈现 | 诊断代码、对象标识、参数、展示所需的物理量 | 翻译不改变 ID、协议关键字、物理输入或结果 |

单位契约必须逐项列明长度、面积、体积、温度、传热系数、换气量、太阳辐射、功率、能量和无量纲比例；区分 Rhino 输入单位、核心单位、引擎单位与显示单位。累计能量和功率不能共用无差别求和规则。EPW 辐射字段的记录单位不能直接作为 `.sol` 单位依据。

几何契约需要定稿平面/闭合/接触容差、局部接触拆分、重叠体诊断、内外/接地/架空边界及人工修正规则。显式窗“未提供”和“明确无窗”应可区分；同面显式覆盖参数化的方案仍属 ADR-009 的 Proposed 规则，定稿前不固化优先级。

日历契约需要定稿模拟起始星期、工作日/周末、节假日、闰年、夏令时、日程端点和引擎支持范围。广州文件的 Sunday 和分钟 30 均是原始信息；不能直接用来源年份的星期重建使用日程。

预设契约逐参数保留发布机构、来源版本、条款/表号、地区/用途、单位、适用条件、数值性质和分发依据。载入后保留最终参数和用户覆盖信息；新预设版本不改变历史运行。具体规范版本与预设数值仍需来源核对及确认。

验收断言：单位等价的几何转换得到等价物理模型；语言变化不改变模型；邻接修正后双方引用和接触面积一致；同一方案的新运行保留独立身份；缺失必需数据在进入引擎前产生具体诊断。

## P3：实现单方案建模与执行主链

在 P1 能力验证和 P2 相应契约定稿后，依次实现几何转换、模型校验、天气/工况/日程组装、窗与太阳前处理、新版协议写出和单次运行。每一步输出可追溯到输入对象，GH 组件仅承担端口、树结构和呈现职责。

必须承接材料与围护、项目北向、地温、HVAC/COP、照明、DHW、泵、管理等级、能源来源及有旧证据的 PV/SWH/风机配置。逐项核实新版字段及实际效果，不因干净切换删除真实输入能力，也不将旧实验组件作为能力承诺。U 值输入不自动扩展为分层构造求解器。

运行准备使用新建且由本次任务拥有的工作目录，将最终协议字节、天气身份及引擎身份绑定到运行记录。目录布局以 P1 确认为准；不修改 Rhino 进程的全局工作目录。进程参数使用明确参数列表和 `shell=False`，路径与显示名称分离；标准输出/错误须持续消费或直接写入本次日志文件，避免等待过程被管道塞满。[Python subprocess](https://docs.python.org/3.9/library/subprocess.html)

成功条件至少同时包含：预期进程结束状态、本次运行产物、必需字段、完整时间轴、可解释单位及有限值。文件存在、文件时间戳或 EXE 退出码不能单独作为成功依据。未知协议/缺列/损坏输出保留原始证据并报错，不按旧列号猜测。

验收断言：闭合平面体与人工核对的几何量一致；非闭合、曲面和重叠输入可定位；局部邻接不吞掉剩余外表面；同一面不会重复计窗；单方案从 GH 真实输入走到指定引擎并读取本次结果；输入变更后的旧结果带原运行身份。

## P4：核实结果与计算正确性

先建立原始列到物理量、单位、时间区间、能源来源和对象的映射，再实现年/月汇总、逐时趋势、冷热累计需求与峰值、各区室温及面积强度。冷热需求、HVAC 输入能耗、其他能源用途和现场发电分别表达；不能将负荷直接标为购入能耗。

建筑峰值先对齐并合成同一时刻的相关功率序列再取峰值，不能相加各区不同时刻的峰值。每个归一化指标明确建筑总面积或受调节面积；零分母为无效指标，不能返回零。差异指标明确基准运行，基准为零时不生成普通百分比。

正确性分两层：同版本引擎、同协议字节的迁移对照，检查外围是否改变输入和解释；独立参考及控制变量案例，检查单位、时间、物理趋势和适用边界。旧程序结果不作物理真值，排序稳定也不替代量纲核对。

验收断言：列换序不改变解析结果，缺少必需列被拒绝；各量采用与其语义一致的聚合；面积变化及非空调面积单列解释；太阳单变量、邻区耦合和坡面案例通过约定参考核对。绝对/相对容差由真实基准确定，不预填无依据精度。

## P5：顺序批次与结果比选

批次提交时检查共同天气、时间轴、使用工况、系统配置规则和引擎版本，冻结方案集合及最终参数。研究变量单独列出；面积引起的人员/设备总量变化按固定密度与规则解释，不强行要求派生总量相等。

同一批次同时只运行一个方案。必须区别方案、运行、批次身份，显式触发启动，GH 重复求解不能重复入队。进度展示已完成数量/总数量和阶段状态；没有内核进度接口时不编造计算百分比。

ADR 中“单方案失败继续其余方案”“取消终止当前进程树”“文档关闭清理所拥有任务”为 Proposed 技术规则。实施前定稿失败策略、进程所有权、完成与取消竞争的终态和宿主回调失效处理。无论采用哪种策略，都必须保留失败证据、避免孤立进程、禁止关闭后访问文档，并保留已完成结果。

验收断言：三方案案例在第二项失败时符合已定策略，第一项成功产物保留；重复求解仅启动一次；取消后无新方案启动且当前任务按契约终止；文档关闭后回调不触碰失效文档；失败和不可比方案不以零值参与排名；重算不覆盖历史。

## P6：预设、国际化与插件交付

完成经核实且具备使用/分发依据的中国办公/住宅预设，逐热区覆盖并保存来源。国际化覆盖组件和端口说明、诊断、运行状态、指标和报告文本；英文基准资源完整，额外译本清单按确认结果交付。用户名称和引擎原始日志保留原文，机器字段和协议关键字不翻译。

依据 P1 验收的发布路径组织可安装插件与共享代码，提供分区建模、非空调缓冲空间、坡屋顶、双路径窗/遮阳和顺序比选的新工作流示例。归档示例继续作为历史材料，不宣称其可以直接用于新插件。

发布门槛包括实际安装/卸载、离线启动条件、依赖布局、英文与所确认译本、非 ASCII 名称/路径、不同区域数值格式、文档关闭与取消、完整主链和已声明功能。插件发布能力不自动赋予引擎或天气的再分发权；若没有相应依据，部署说明应定位用户持有的完整引擎目录和天气文件。

验收断言：目标版本 Rhino 可安装并加载插件；示例使用真实新版输入输出；切换语言和显示单位不改变规范化物理输入；预设数值可逐项定位来源；重载已保存方案保留最终参数及运行关联。性能说明给出实际机器、方案/热区规模和测量口径，不以未经测试的范围作为支持承诺。

## 后续模块落位与定稿点

下表只用于约束职责和后续文件变更范围；除 02、03 的新文件外，名称和拆分仍是 ADR-004 下的候选落位，不是本次要创建的空文件或已批准公共 API。单一职责能由函数和明确数据对象承担时，不预建服务框架、插件系统或抽象继承层。

|---|---|---|
