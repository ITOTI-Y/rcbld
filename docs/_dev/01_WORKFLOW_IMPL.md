# 从 Rhino 操作开始的实现顺序

先做一个能够接入房间、指出几何问题并显示面积和体积的 Grasshopper 组件。用户在 Rhino 中看清输入是否正确，再继续设置围护、窗、材料、使用条件和计算参数。

本文说明完整使用流程。本轮的完整代码在 [热区接入与检查](02_ROOMS_IMPL.md)，只交付下面的第 1 步。每个后续步骤都从用户当时要完成的操作出发，再确定需要的数据和函数。

## 用户的操作顺序

| 步骤 | 用户做什么 | 组件提供什么 | 传给下一步什么 |
|---|---|---|---|
| 1．接入热区 | 引用 Rhino 中已分好的房间实体，或接入 GH 生成的实体；按需填写名称 | 闭合、平面和单位检查；几何预览；体积、围护面积和错误位置 | 全部通过检查的一组热区及其米制几何副本 |
| 2．检查围护与邻接 | 查看墙、屋顶、楼板与相邻房间的接触；修正边界判断 | 可在视口中对应到具体面的分类和邻接结果；局部接触单独处理 | 已确认的围护面、接触关系及边界条件 |
| 3．设置建筑条件 | 配置窗、遮阳、材料和房间使用条件；需要时覆盖个别房间或面 | 当前有效设置及其作用对象；缺失参数和冲突说明 | 几何与热工、使用条件、日程的明确对应关系 |
| 4．选择天气并运行 | 选择 EPW、完整引擎目录和结果位置；明确触发计算 | 运行前检查、运行状态、取消入口及失败原因 | 属于本次输入的计算结果和日志 |
| 5．查看结果 | 选择建筑或热区，查看能耗、冷热需求和室温变化 | 带单位和时间范围的结果；明确区分需求与设备能耗 | 可以回到原方案和输入条件的结果 |
| 6．保存和比较方案 | 保留当前方案，再修改设计变量；选择方案进行比较 | 可重新打开的建模关系、计算记录和对比结果；标明共同条件与差异 | 用户可以继续编辑、重算或导出的方案 |

第 1 步的 `ready` 只表示本组件的检查通过。房间之间是否重叠、哪些面接地、窗是否落在墙面上，以及引擎是否支持最终模型，分别由后续步骤处理。

## 本轮需要手动创建的文件

按表中顺序创建文件。代码先保存在仓库，再完整复制进 GH 的 Python 3 Script 组件；修改代码后，同步更新组件内的脚本。

| 顺序 | 文件 | 用途 |
|---|---|---|
| 1 | [grasshopper/rooms.py](../../grasshopper/rooms.py) | 完整的热区检查代码，包含数据对象、检查函数和组件入口 |
| 2 | [examples/rooms.gh](../../examples/rooms.gh) | 按下一份文档设置端口、连接预览和文字组件，再保存为 GH 定义 |

运行位置是 Rhino 8 中的 GH Python 3 Script。Rhino 8 使用 CPython 3.9.11；本轮只使用标准库和宿主自带的 RhinoCommon、Grasshopper API，无需另装 Python 包。[Rhino Python 版本说明](https://developer.rhino3d.com/guides/rhinopython/what-is-rhinopython/)

本轮不修改项目配置，不创建独立项目存储，也不提供测试文件。热区检查代码不写入 Rhino 文档、不调用引擎、不生成窗或分析邻接。保存 `.gh` 是保存建模连线；如果其中引用了 Rhino 对象，还应保存对应的 `.3dm` 文件。

## 第 1 步的输入与输出约定

输入列表中的每个实体代表一个热区。组件不自动合并房间，也不自动把一个实体拆成多个房间。名称用于显示，输入顺序用于定位；同名房间可以保留，报告仍能通过序号区分。

`rooms` 输出中的每个 `Room` 对象包含：

| 字段 | 含义 |
|---|---|
| `source_index` | 本次输入列表中的位置，从 0 开始；报告中的房间序号从 1 开始 |
| `name` | 显示名称；未提供名称时使用 `Room 1`、`Room 2` 的顺序名称 |
| `brep_m` | 单位为 m 的独立 Brep 副本，实体朝向统一向外 |
| `volume_m3` | 热区体积，单位为 m³ |
| `envelope_area_m2` | 该实体全部边界面的面积之和，单位为 m² |
| `tolerance_m` | Rhino 文档绝对容差换算成 m 后的值 |

围护面积包含房间的全部边界面。它不表示楼地板面积，也不表示已经扣除相邻房间接触面的建筑外表面积。当前几何可以包含坡面和非正交平面；是否能用于后续引擎计算仍需后续检查。

`source_index` 是本次求解的位置，不是永久标识。调整列表顺序或插入房间后，它会改变。后续组件按本次输入继续处理；方案保存时再明确持久标识与修改规则。

`brep_m` 用于后续计算，`preview` 和 `invalid` 使用原模型单位，用于与 Rhino 源模型重合显示。后续组件如果要修改 `brep_m`，先复制；显示几何使用预览输出，避免把米制副本直接显示在毫米模型中。

## 本轮完成边界

组件应在同一次求解中检查整组输入。所有房间通过时，`ready=True`，并按输入顺序输出全部 `rooms`；任一房间失败时，`ready=False`，`rooms` 为空，同时保留成功房间的预览及错误说明。修改输入后，输出反映本次求解，不保留上一次的成功状态。

同一尺寸的米制和毫米制模型应得到一致的 m²、m³ 结果。检查与换算只读取源对象；朝向修正和坐标换算发生在副本上。平面检查使用所属 Rhino 文档的绝对容差，不自动修补、封口或把曲面替换成平面。

目前尚未在运行中的 Rhino/GH 中验证原生几何测量、预览显示，以及自定义 `Room` 对象在组件间传递的行为。实施时需在 Rhino 中核对这些行为；临时环境的代码检查不能替代宿主验证。
