# 完整重构实施总览

本方案按已确认的产品需求重新设计 RCBld。归档源码、发布包、上游仓库、示例、天气和逆向记录用于调查与验证；它们不定义新产品的数据模型、组件结构或持久化格式。现有 RCBldEng 保留为外部计算后端，由独立适配器承接其协议。运行时选择引擎安装位置并记录实际身份，不设置某个发布包或 SHA-256 的准入白名单。

本轮交付是手工实施文档：本文给出完整路线和既有记录的准确修订内容，[05](05_MODEL_IMPL.md) 与 [06](06_PROJECT_IMPL.md) 给出首阶段完整代码。实际代码落地后才能称为首阶段实现；本文不表示插件或计算链已经完成。01–03 保留为历史核查方案，不作为新实现的前置步骤，不执行其中的固定发布包门槛或测试文件创建步骤。

## 已确认需求与范围

| 需求 | 新产品必须提供的行为 |
|---|---|
| 主入口 | Rhino 8+ / Grasshopper；Python 3.9.11；当前开发分支为 `dev`；核心可在普通 Python 中导入 |
| 完整重构 | 新组件、端口和示例；不要求旧 GH 定义兼容；归档资料保留 |
| 几何 | 用户提供已分热区的闭合 Brep；平面围护含非正交墙、坡屋顶；曲面由用户先简化；识别边界和邻接并允许修正 |
| 热工输入 | 有明确单位的有效热工参数；首版不实现分层材料构造求解器；保留真实面、面积、法线、体积和北向 |
| 工况 | 中国办公/住宅优先，预设有来源、版本与适用条件；允许逐区覆盖；人员、设备、通风及日程独立于温控状态 |
| 非空调区 | 保留内部得热、通风、自由室温和邻区传热需求；不以无人、绝热或极端设定温度替代 |
| 窗与遮阳 | 默认参数化，支持显式窗、遮阳与周边遮挡；同一面的显式窗覆盖参数化窗，显式无窗必须有效 |
| 项目保存 | GH 保存可编辑建模关系；独立项目目录保存规范化模型、配置、修订和运行历史；不把原始 Brep 序列化进核心 JSON |
| 比选 | 固定系统与使用工况比较建筑设计变量；整组提交、顺序计算、汇总成功与失败，不设任意方案数上限 |
| 失败语义 | 单方案失败后继续其他方案；共同输入无效时拒绝整批；基础设施故障导致不能继续时停止并保留原因 |
| 引擎能力 | 不支持的模型仍可保存；能力检查阻止相应计算并定位原因，不静默近似或缩减需求 |
| 结果 | 能耗、冷热需求、峰值、趋势和热区室温；明确时间轴、单位、能源边界和面积分母；失败不填零 |
| 国际化 | 英文基准文本与独立 i18n 资源；界面语言不改变地区工况、物理输入和结果；额外语言清单另行确定 |

本轮不实现替代引擎、自动分热区、气流网络、系统寻优、云服务、数据库或独立 Web/桌面产品。用户允许未来讨论替代引擎；是否替换需要独立的算法范围、参考案例与数值验收依据，不与外围重构绑定。

## 阶段顺序与完成边界

阶段划分决定交付顺序，不删减最终功能。各阶段只有达到本行断言才算完成；Windows/Rhino 暂不可用时继续可独立实施的部分，保留目标环境验收缺口。

| 阶段 | 交付内容 | 完成断言 |
|---|---|---|
| S1 领域与项目基础 | 05 的类型、单位、引用诊断；06 的方案修订、输入快照、JSON 保存与重载 | 普通 Python 3.9.11 可导入；保存和重载保留完整首阶段数据；历史不可被后续编辑或保存覆盖 |
| S2 几何适配 | 单位转换、闭合/平面校验、北向、面拆分、真实邻接、人工修正、几何预览 | 正交、旋转、非正交和坡屋顶案例保持真实面积/体积/法线；部分接触拆成对应子面；重叠、错位和曲面有对象诊断 |
| S3 工况、天气与系统 | 有据预设、覆盖记录、日历展开、天气解析和时间对齐；地温、HVAC/COP、照明、DHW、泵、管理规则、能源来源及 PV/SWH/风机发电配置 | 每个有效输入能追溯来源与单位；日历与天气无静默补值；非研究条件可比较；相关输入对后端的实际效果逐项核实 |
| S4 窗与太阳 | 参数化窗实体化、显式窗匹配、简化遮阳、显式遮挡与周边建筑、按面太阳前处理 | 明确无窗不会重新生成窗；无重复面积与重复遮挡折减；辐照、透射与吸收热量分开，全部时序对齐 |
| S5 引擎适配与单次运行 | 选定安装目录、能力检查、协议转换、独立工作目录、启动/取消、退出与产物检查、结果语义解析 | 实际引擎完成受控单方案案例；日志和产物属于本次运行；不支持的能力阻止运行但不阻止模型保存 |
| S6 批次与比选 | 共同条件核查、冻结输入、顺序队列、取消、运行终态、历史与结果比较 | 一个失败方案不吞掉其他结果；共同错误在启动前拒绝；基础设施故障停止；旧结果明确关联旧快照；峰值基于同步时序 |
| S7 GH 与安装交付 | 薄组件、DataTree 映射、预览/烘焙、显式命令、后台调度、英文/i18n、新例子、可安装包 | 多次求解不重复提交；关闭文档后无失效回调；语言切换不改物理模型；Windows/Rhino 实际安装、计算和重载通过 |
| S8 数值与发布验收 | 同引擎迁移对照、控制变量案例、独立物理参考、真实规模性能记录 | 量纲、时间、邻接、非空调、太阳及能量聚合有证据；精度容差来自参考案例；不把历史 CSV 或排序一致当作物理正确 |

S3 和 S4 的数据扩展必须先给出明确语义，再发布新模型 schema 和显式迁移实现。S1 的 `rcbld.model/1` 是领域基础快照，不是完整模拟请求，不能向其中塞入未定义的系统、遮挡或引擎参数。能力不支持与模型结构错误分开；保存成功和语义诊断为空都不代表可以计算。

## 跨阶段接口

| 生产方 → 消费方 | 数据及责任 |
|---|---|
| GH → Rhino 适配 | 宿主对象和用户选择；GH 不承担几何算法或文件协议 |
| Rhino 适配 → 核心 | 米制坐标、有效多边形及洞、真实面积、外法线、热区体积、边界关系和明确容差；不传 Brep/DataTree |
| 工况/日历 → 核心 | 使用密度、独立温控状态、来源与覆盖记录、按共同时间轴展开的比例或温度日程 |
| 核心 → 项目 | `BuildingModel`；允许保存可解析但仍有语义诊断的草稿，保留对象定位供修正 |
| 项目 → 运行应用层 | 已保存修订和不可变输入快照；S1 的 `InputSnapshot` 仅冻结领域输入，尚无执行状态和计算结果 |
| 天气/太阳 → 引擎适配 | 带单位、时间轴和来源的物理数据；辐照、入射能量、透射热量的区别在这里显式表达 |
| 引擎适配 → 运行应用层 | 能力诊断、实际后端身份、准备好的协议文件及本次工作目录；调用方决定启动或拒绝 |
| 结果解析 → 比选/GH | 按名称定义的物理量、单位、时间轴、对象标识、能源与面积边界、诊断；展示名称不作为内部键 |

调用保持普通函数与明确数据对象。当前只有一个后端，不预建插件注册中心、抽象求解器层级或通用任务框架。未来替代引擎可以消费相同物理模型，但无需现在为未知求解器建立接口占位。

项目目录由用户明确选择。S1 只生成一个 `project.json`，其中包含多个方案、不可变修订及输入快照；S5/S6 再实现天气副本、协议文件、日志和结果的运行目录及索引。引擎要求的 `Projects` 布局、`.sim/.sol` 名称和命令行只属于 S5，不约束项目目录。快照中的天气位置与哈希是资产引用，不是已保存天气字节或可重跑证明。

不附测试代码文件，也不要求实施 03 中的测试文件。首阶段验收对应以下可观察断言：

- 模型和项目模块在普通 Python 3.9.11 导入，不读取引擎路径，也不导入 Rhino/GH。
- 非有限物理数值、字符串冒充数值、非法枚举及未知字段在构造/加载边界失败；语义诊断包含代码、对象 ID、字段及关联 ID。
- 重复 ID、悬空引用、错误日程单位或长度、不对称邻接及邻接面积/热工属性不一致能够定位；发现重复 ID 后先返回该错误，避免基于歧义引用继续判断。
- 同一面 WWR 为 0.5 时采用参数化面积；显式空窗集合得到零窗面积；提供显式窗时只统计显式面积；超过围护总面积报错。
- 非空调区仍引用使用工况，保持人员、内部得热和通风；温控设定仅属于受调节路径。
- 保存与重载保留中文名称、单位值、对象标识、几何、来源、方案修订和快照摘要；未知/缺失 schema、重复 JSON 键、损坏快照被拒绝。
- 后续编辑产生新修订，旧修订和快照保持原值；保存接口拒绝覆盖已有历史和过期的磁盘版本。
- 写入、刷新或替换失败发生在提交前时，旧 `project.json` 字节不变且仍可重载；本次临时文件清理。进程被强制终止可能留下临时文件，但加载器只读取正式文件。
- 可解析的语义错误草稿可以保存；`capture_input` 拒绝含语义错误的模型。几何有效性、天气可用性、后端能力和完整计算请求在后续阶段检查，不以 S1 的快照创建冒充通过这些检查。

```markdown
- 方案继续以设计变量为比较对象，系统与使用工况保持共同规则。单方案失败后继续，共同输入无效时拒绝整批，基础设施故障停止并保留原因。
- 不支持的能力不影响模型保存；对应计算由引擎适配层明确阻止。非空调、非正交/坡面、显式遮挡和结果量纲均须单独验收。
- 顺序为领域与项目基础、几何、工况/天气/系统、窗/太阳、引擎单次运行、批次比选、GH 安装交付和数值验收。允许独立工作提前进行，不跳过目标环境的最终门槛。

待补证据仍包括 Windows/Rhino 安装与执行、完整太阳及结果语义、经核实的预设资料、最低宿主版本、物理参考与数值容差。首阶段输入快照不包含完整运行请求、运行日志或计算结果，也不证明外部天气字节可用；这些属于后续阶段的明确交付。
```

```markdown
| 日程 | 共同时间轴上的使用比例或温度设定序列 | 日历规则由日程模块展开；旧 BUS/ITSS 表格布局只属于后端映射 |
| 温控 | 明确的自由浮动或供暖/制冷设定路径 | 自由浮动不是缺失 HVAC 输入的隐式结果 |
| 天气资产引用 | 数据位置与内容摘要 | 引用不是天气副本，摘要不是引擎版本白名单 |
| 太阳输入 | 按面、时间和单位定义的辐照或太阳得热物理数据 | 入射辐照、透射得热和吸收得热不同；.sol 的排列和换算属于适配器 |
| 参数化窗 | 窗墙比等规则生成的窗输入 | S1 保存比例并求面积；实体布局由几何阶段生成 |
| 显式窗 | 关联围护面的明确窗集合 | 覆盖同一面的参数化窗；空集合与未提供分别表示明确无窗和无覆盖 |
| 遮阳与遮挡 | 简化遮阳、显式构件及周边建筑对太阳辐射的影响 | 同一作用不重复折减；周边建筑不自动成为热区 |
| 系统配置 | HVAC、DHW、泵、管理规则、能源来源和发电等共同条件 | 不混同冷热需求与购入能耗；不新增系统寻优 |
| 项目 | 独立保存和重载的一组方案及其历史 | project_id 与建筑、方案、修订及运行标识分开 |
| 比选方案 | 一套用于设计比较的模型及配置的修订序列 | 同一方案可有多个修订和多次运行 |

| 输入快照 | 绑定方案修订的不可变输入及内容摘要 | S1 仅冻结领域输入，不代表已启动、已通过后端能力检查或产生结果 |
| 模拟运行 | 对确定完整输入执行一次计算的任务 | run_id 独立；旧 first_run 目录规则不进入领域模型 |

| 模拟结果 | 有单位、时间轴、能源边界、对象关联和诊断的数值输出 | 文件存在、进程退出或历史 CSV 都不等于本次结果有效 |
| 国际化 | 英文基准及独立的展示文本资源 | 稳定 ID、物理输入、来源与引擎关键字不随语言变更 |
| SuperBrep / BUS / ITSS / BusData | 历史实现术语 | 保留用于阅读归档，不作为新类型、端口或文件格式依据 |

关系为：宿主几何与显式配置形成规范化模型，模型编辑形成方案修订，修订冻结为输入快照，完整请求经能力检查与引擎适配形成运行，运行产物经语义核查后参与比选。需求已确认不代表现有后端能力已验证。
```
